# Operator runbook — Hermes, interactive session
This package is prepared in Git but has not been executed locally. Start with no paid calls. Keep existing MapOS cron and production untouched. 
1. Clone branch benchmark-mapos into dedicated operator-only checkout. Record commit, verify package hashes and read config.json and PROTOCOL.md. Python >=3.12 required for archive filter. No candidate access to this checkout, GitHub or sibling outputs. Inspect actual Hermes CLI/provider interfaces locally, use existing supported isolated sessions; do not guess flags. Document exact adapter and verify model/provider/effort preflight without paid inference if possible, otherwise request authorization for minimal probes. No reconfiguration of the active MapOS cron.
2. From repo root: python3 benchmark_mapos/prepare.py plan > /dedicated/operator/plan.json (substitute actual new safe directory). For each T01,T02,T03 create reference and starter controls with python3 benchmark_mapos/prepare.py prepare T01 reference /dedicated/workspaces/control-t01-ref (similarly starter; new paths each). The script exports pinned native tree only, initializes a fresh git history and adds TASK.md; no hidden graders are copied. No remote in candidate worktree. Verify that the archive excludes prototype/history and model cannot reach controller or another attempt. Check production unchanged. 
3. Reuse qualified benchmark-only runtime, not the ongoing MapOS lab DB or production service. PHP 8.5, locked Composer deps, mysqli, SQLite for native regression. Use dedicated isolated MySQL 8.4 with fresh schema for each control/trial; use schema-producao.sql and dados-laboratorio.sql from the pinned schema commit. Import schema then fixtures; verify FK checks active; no real records. Lab user named bench_* with privileges only on mapos_bench_* dedicated schema, not root. Explicit BENCH_DB_HOST (isolated service name/IP, not localhost), BENCH_DB_NAME, BENCH_DB_USER, BENCH_DB_PASSWORD passed securely to grader environment only; never print them or send to model. Confirm actual target identity before any SQL. Grader requires pristine fixture (2 OS, 1 stock event, product 1 stock 8). Fresh DB for every grading invocation. 
4. Install dependencies using native composer.lock in isolated runtime; check PHP extensions. Trusted evaluator in separate isolated PHP runtime with grader file and fresh native export+submitted allowed model files, original tests and dependencies, no network/no model credentials. Run: php /operator-private/grade.php T01 /grade/native (adjust only paths/task, never alter grading). Exit 0 all held-out pass; 1 material failure; 2 preflight/infra. Capture output JSON and stderr separately; invalid JSON or fatal infrastructure error requires diagnosis, not a model zero. Run frozen native PHPUnit regression command (derive exact executable from composer/CI; tests original) against candidate code, preserve logs. Run controls for all tasks; T01/T03 reference is pristine native, T02 reference adds batch method. Expect starter T01/T03 critical failures, T02 missing method failures. Record grade output, regression, actual commands, hashes and no-op sensitivity. Review with GPT before any paid queue. Do not expose failure details to candidate.
5. After GPT/owner approves controls, budget and exact adapters, use plan.json order. For each fresh ID, prepare its task starter, fresh synthetic candidate DB and isolated agent session. Prompt only TASK.md plus identical standard instructions: respect scope, use supplied tool/test environment, finish with diff and honest status, no external model/reviewer, no network except provider. Allowed files in config.json, communicate only task-relevant allowed paths. Same 45-min cap if accepted, no follow-up, preserve artifact even if stopped. Record all calls/time/tokens if exposed. Terminate candidate session safely before grading; no concurrent writes. Copy only allowed changed model code onto clean evaluator workspace, original trusted tests unchanged; audit full diff incl untracked files. Keep REVIEW.md for blinded scoring. Recreate pristine grading DB and run same commands as controls. Do not leak hidden checks or reference. 
6. Record attempt using record.example.json; one file per ID, no overwrites. Store raw evidence only locally redacted; include compact per-case outputs, diff hashes, exact tool identity and test logs necessary to audit. Run python3 benchmark_mapos/summarize.py /dedicated/operator/records to generate summary Markdown. Independent assessor applies private/REVIEW-RUBRIC.md after anonymization, record findings 0-3 and false positives. If results missing, classify pending/invalid not PASS. 
7. Publish only reviewed compact results and report under benchmark_mapos/results/<campaign-id>/ on branch benchmark-mapos; pin input revision and grader hashes. No pushes by candidates, no real data, passwords, auth files or full logs. No changing other branches or cron. Notify GPT Supervisor with commit and separate preflight/paid status. 
## Important limits
The adapter, sandbox, database lifecycle and PHP grader have NOT been validated on your host. This is intentional: preflight is an acceptance gate, not a claim of runtime readiness. Do not treat the Python preparation script as an automatic end-to-end model launcher. If local tool limitations prevent equal, isolated execution, stop with evidence.
